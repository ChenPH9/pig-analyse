# 牧原股份数据采集系统重构 - 产品需求文档

## 概述

- **摘要：** 重构牧原股份财务和母猪数据采集系统，扩展数据源至东方财富、新浪财经、巨潮资讯、国家统计局、农业农村部，实现每日定时更新和数据融合
- **目的：** 解决当前依赖模拟数据和有限数据源的问题，建立稳定、实时、多源的数据获取和展示系统
- **目标用户：** 财务分析人员、农业行业分析师、投资者

## 目标

- [ ] 整合5个数据源（东方财富、新浪财经、巨潮资讯、国家统计局、农业农村部）
- [ ] 实现每日8:30定时自动更新数据
- [ ] 建立数据验证与合并策略，确保数据质量
- [ ] 实现数据持久化和缓存机制
- [ ] 保持现有前端展示不变，仅更新后端数据源

## 非目标

- 不重写前端展示界面
- 不改变现有API接口格式
- 不新增复杂的数据分析功能

---

## 背景与上下文

现有系统已搭建前端（React+TypeScript+Tailwind）和后端（Express.js），但主要依赖历史模拟数据。爬虫框架已存在，但数据源有限。用户要求完全重写爬虫，增加更多真实数据源，并实现定时更新。

## 功能需求

### FR-1: 多数据源爬虫系统
- 支持东方财富财务数据获取
- 支持新浪财经实时股价获取  
- 支持巨潮资讯公告数据获取
- 支持国家统计局宏观养殖数据获取
- 支持农业农村部母猪存栏数据获取

### FR-2: 数据验证与合并引擎
- 实现数据源优先级配置
- 实现跨源数据一致性检查
- 实现缺失数据自动填充策略
- 异常数据检测与标记

### FR-3: 定时调度系统
- cron表达式配置：每天8:30触发更新
- 支持手动刷新接口
- 更新状态追踪与日志记录

### FR-4: 数据持久化
- 本地JSON文件备份
- 数据版本管理
- 历史数据可回溯

## 非功能需求

- **NFR-1:** 数据更新完成时间 < 5分钟
- **NFR-2:** 爬虫失败时自动重试（最多3次）
- **NFR-3:** 数据缓存TTL 24小时
- **NFR-4:** 支持并发获取多个数据源

## 约束

- **技术:** 保持现有技术栈（Node.js+Express+TypeScript）
- **依赖:** 现有依赖 axios, cheerio, node-cache，新增 node-cron
- **合规性:** 尊重各网站robots.txt，合理设置请求间隔

## 假设

- 各网站API和页面结构保持稳定
- 国家统计局和农业农村部数据以公开方式可获取
- 每日8:30更新时间在业务时间范围内

---

## 验收标准

### AC-1: 多数据源爬虫正常工作
- **给定:** 系统启动后
- **当:** 调用数据获取API时
- **则:** 系统能从所有5个数据源获取数据，至少3个源返回有效数据
- **验证:** programmatic
- **Notes:** 通过测试脚本验证各数据源连接

### AC-2: 定时任务每日执行
- **给定:** 系统运行中
- **当:** 时间到达每天8:30
- **则:** 系统自动触发数据更新流程
- **验证:** programmatic
- **Notes:** 通过cron任务测试验证

### AC-3: 数据合并策略正常工作
- **给定:** 多个数据源返回数据
- **当:** 数据存在冲突或不一致时
- **则:** 系统按优先级规则合并，保留高质量数据
- **验证:** programmatic + human-judgment
- **Notes:** 检查合并逻辑和数据质量

### AC-4: 前端展示不受影响
- **给定:** 后端系统升级完成
- **当:** 用户访问网站
- **则:** 前端展示与之前一致，数据质量提升
- **验证:** human-judgment
- **Notes:** 人工检查前端展示效果
